## Задача

TP лонга, введённый ниже марка (опечатка: `300` вместо `3300`), терминал подаёт как есть — из тикета
(`TradeForm.tsx:161-175`) и из диалога позиции (`TpSlDialog.tsx:54-66`). Шлюз цену триггера не
сверяет, `conditional-svc` срабатывает на первом тике, позиция закрывается по рынку через полсекунды,
вторая нога снимается по связке. Зеркально — SL выше марка у лонга и оба случая у шорта.

SDK 0.57.0 даёт одну проверку — `validateBrackets` в `@liq/core` с парными `describeBracketRejection`
/ `describeBracketWarning` — и делает `markPrice` обязательным входом `useApplyBracketsMutation`:
действие не подаёт отклонённую ногу. Для диалога этого хватило бы, для тикета — нет: скобки входа
подаются из `onSuccess` входа, и отказ в действии оставил бы принятый вход без стопа. Поэтому тикет
судит скобки **до** входа.

## Решения

1. **Бамп и правка вызывающих — один коммит.** `markPrice` в `ApplyBracketsInput` обязателен: бамп сам
   по себе оставляет типизацию красной.
2. **Результирующая позиция — один расчёт.** «Позиция, которой станет рынок после входа»
   (`открытая + вход`, сторона по знаку) сейчас считается внутри `attachBrackets`, после принятого
   входа. Расчёт выносится в чистую функцию; ею пользуются и гейт кнопок, и `attachBrackets` — иначе
   гейт и подача разойдутся ровно там, где это стоит денег. Остаётся в терминале: три строки над
   `toSignedSize`, доменного правила в них нет.
3. **Каждая кнопка судит свою результирующую позицию,** не «сторону кнопки»: Buy —
   `открытая + вход в лонг`, Sell — `открытая + вход в шорт`. Лонг 2 и продажа 1 → для Sell скобки
   судятся как скобки лонга. Нулевой результат (полное закрытие) не судится — это решает сама
   проверка SDK (`closingOrderFor` → `null`, вердикт пуст), гейт его не выделяет.
4. **Раздельный `disabled` у кнопок.** Общий гейт тикета остаётся, к нему у каждой кнопки добавляется
   вердикт её стороны. Надписи кнопок не меняются (решение макета в `SubmitButtons.tsx`).
5. **Опорные цены.** Марк — всегда. Лимитная цена входа — вторая опорная только на вкладке Limit и
   только когда на рынке нет открытой позиции; при открытой позиции скобки принадлежат ей, опорная
   цена одна. То же правило — в `attachBrackets`, чтобы действие судило теми же числами, что гейт.
6. **Одна строка под полями TP/SL** (`entry-tpsl-validation`), три состояния:
   скобки годятся обеим кнопкам или не заполнены — строки нет; годятся одной — приглушённая подсказка
   `TP/SL fit a long only` / `TP/SL fit a short only`; не годятся ни одной — красная причина по обеим
   сторонам: `Long — Take profit: must be above mark · Short — Stop loss: must be above mark`. Строка
   причины — `describeBracketRejection` как есть: тот же текст, что действие печатает в `trade-error`.
7. **Судится только включённое.** Тумблер TP/SL погашен или оба поля пусты — вердикта нет, кнопки
   живут по общему гейту.
8. **Диалог позиции.** Сторона известна. Вердикт — от `row.markPrice` и `row.position.liquidationPrice`,
   пересчитывается на живом марке. Отказ → Save неактивна, причина строкой `tpsl-validation` — отдельно
   от `tpsl-error`, где печатается отказ шлюза: «не отправили» и «отправили и отказано» не смешиваются.
   «SL за ликвидацией» → строка `tpsl-warning`, Save активна.
9. **Марка нет — «не готово».** В тикете это уже закрыто общим гейтом (`tabPriceReady`, погашенный
   тумблер при `markPrice === 0n`). В диалоге Save неактивна, пока у строки нет марка; текста нет —
   `describeBracketRejection` для `not-ready` молчит, как `describeRejection`.
10. **Вне объёма:** карточки 8–12 обзора 18.09; проверка на шлюзе (#789); kwenta.

## Тесты

- Правило цен — в SDK, с его юнитами (`position-brackets-check.test.ts`,
  `applyBracketsMutation.test.tsx`). В терминале один юнит — `resultingPosition`: нет открытой позиции;
  доливка; частичное закрытие сохраняет сторону; переворот меняет сторону; полное закрытие → размер
  `0n`; размер открытой по модулю (часть источников несёт его без знака — `toSignedSize`).
- `e2e/tier1/04-trade-market.spec.ts`: TP ниже марка → Buy неактивна, Sell активна, подсказка
  `fit a short only`, `world.submittedOrders` пуст после попытки; TP и SL оба ниже марка → обе кнопки
  неактивны, красная причина; вкладка Limit без позиции: SL между лимитной ценой и марком → Buy
  неактивна; тот же SL при открытом лонге → Buy активна (лонг в фикстуре — **без** существующих
  скобок: тикет отдаёт действию настоящие скобки позиции, и пустое поле TP при живом TP — это его
  снятие; тест про опорную цену не должен заодно проверять отмену).
- `e2e/tier1/28-position-actions.spec.ts`: TP ниже марка у лонга → Save неактивна, `tpsl-validation`
  видна, на провод ничего; SL за ценой ликвидации → `tpsl-warning`, Save активна, скобка подана.
- Page object: `entryTpslValidation`, `tpslValidation`, `tpslWarning` — только добавления.
- Живая проверка на staging не нужна: при отказе на провод ничего не уходит. Обычный смоук после бампа.

## Риски

- `@liqpro/liq-*@0.57.0` должен быть виден в npm до первой задачи: `npm view @liqpro/liq-core version`.
  Публикация — руками владельца после тега `liq@0.57.0`.
- Марк в замыкании `attachBrackets` — на момент клика; к `onSuccess` входа цена могла уйти, и действие
  отклонит ногу, которую гейт пропустил. Это законный отказ: он виден в `trade-error` с именем ноги,
  как любой отказ ноги сегодня.
